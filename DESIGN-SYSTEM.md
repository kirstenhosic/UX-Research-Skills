# UX Research — Design System & Output Standards

All research plans, deliverables, and documents generated by skills and agents in this repo follow a consistent design system and output standard.

## Purpose

Ensure that all artifacts produced by research skills maintain:
- **Professional quality** — Ready for stakeholder presentation
- **Consistent styling** — the U.S. Web Design System (USWDS) palette and the Public Sans typeface
- **Structural integrity** — Research findings are clear and traceable
- **Team alignment** — All outputs follow the same framework

## When to Apply

**Apply these standards to:**
- Research plans, rationales, and briefs (via the **Research Document Template** skill, `skills/research-document-template.py`)
- Findings reports (via the `research-findings-report/` skill, rendered through the Research Document Template)
- Readout decks (via `research-readout-deck/` generator)
- Data analysis outputs
- Competitive analysis matrices
- Any document generated for stakeholder review

**Skip these standards for:**
- Participant impact summaries — they are plain email, and the reader's mail client owns the styling; structure and rules live in `skills/participant-impact-summary/` and `EVALUATION-LOOP.md` §4.9
- Internal notes and scratch work
- De-identified transcripts (maintain anonymity over styling)
- Raw data files (CSVs, JSON, etc.)
- Working documents (use during analysis, discard after synthesis)

## Color Palette

All documents, decks, the participant card, and PDFs use the **U.S. Web Design
System (USWDS)** theme color tokens
([designsystem.digital.gov/design-tokens/color](https://designsystem.digital.gov/design-tokens/color/theme-tokens/)).
USWDS is public domain, so any team can use it without a brand owner's
permission, and its default palette was built to meet WCAG AA:

| Element | USWDS token | Hex | Usage |
|---------|-------|-----|-------|
| Primary Title | `primary` | #005EA2 | Document title, main headings (H1), callout titles, accent rules |
| Section Heading | `base-dark` | #565C65 | Subtitle, subsection headings (H2) |
| Callout/Highlight | `base-lightest` | #F0F0F0 | Key findings, decision points, callout boxes (with #005EA2 left accent bar) |
| Body Text | `ink` | #1B1B1B | All body text and paragraphs |
| Metadata/Footer | `base-dark` | #565C65 | Cover metadata, page numbers |
| Table Header | `base-lightest` | #F0F0F0 | Table header background (bold #1B1B1B text) |
| Borders and rules | `base-lighter` | #DFE1E2 | Table rules, card borders, dividers |
| Dark anchor | `primary-darker` | #162E51 | PDF cover and deck title, divider, and closing backgrounds |

Status colors, used only for severity or sentiment and never as the accent:
`success` #00A91C (text: `success-darker` #216E1F), `error` #D54309 (text:
`error-dark` #B50909), `warning` #FFBE2E (a fill only, always with `ink` text),
`info` #00BDE3 (text: `info-darker` #2E6276).

**Rationale:** `primary` is the single accent; text lives in the gray family
(`ink` body, `base-dark` secondary). One accent, restrained, AA-contrast pairings
throughout. Measured contrast: `ink` on white 17.2:1, `primary` on white 6.7:1
and on `base-lightest` 5.9:1, `base-dark` on white 6.7:1 and on `base-lightest`
5.9:1, white on `primary-darker` 13.6:1. `primary` appears only on white or light
surfaces, never as text on a dark fill. Don't use `base` (#71767A) for small
text — on `base-lightest` it measures 4.0:1, under the AA bar.

A team with its own brand palette can swap it in, as long as it keeps the same
discipline: one accent, light-dominant, AA contrast on every text pair.

visual identity. Documents generated before that date carry the previous
palette and typeface.)*

## Typography & Spacing

**Document font: Public Sans** — set on the Normal style so every element (body, lists, tables, footers) inherits it. Line spacing: 1.15. Margins: 1" all around. Public Sans is free and open source (SIL Open Font License; [github.com/uswds/public-sans](https://github.com/uswds/public-sans), also on Google Fonts), and the PDF export bundles it, so installing the files in `skills/research-pdf-export/assets/fonts/` gets Word the exact face too. Where a reader's machine lacks it, Word substitutes a system sans automatically — never force a serif fallback. Monospace, where needed: Roboto Mono.

**Page furniture (every page):**
- **Header** (via `page_header` config): bold 9pt title line in the `primary` blue + `base-dark` 9pt context line, separated from the body by a thin accent rule
- **Footer**: confidentiality note (via `footer_note` config, e.g. "Confidential — Internal Use Only") italic at left, 9pt page number at right — or a centered page number when no note is set

**Heading hierarchy:** Title ~28pt → H1 16pt → H2 13pt → body 11pt.

### Document Structure

**Title Page:**
- Main Title: 28pt, Bold, `primary` (#005EA2)
- Subtitle: 16pt, Bold, `base-dark` (#565C65)
- A thin #005EA2 horizontal rule under the title block
- Metadata: 10pt, Regular, `base-dark` (#565C65)
- Space Before Title: 152400 EMU (1 inch)
- Space After Title: 50800 EMU (0.35 inch)

**Headings:**
- Heading 1: Bold, `primary` (#005EA2), numbered "1.", "2." by Word's own numbering (the number is `primary` bold too), so sections renumber live and omitted sections never leave gaps
- Space Before: 101600 EMU
- Space After: 63500 EMU
- Keep-with-next enabled (no orphaned headings at page bottoms)

- Heading 2: Bold, `base-dark` (#565C65)
- Space Before: 63500 EMU
- Space After: 38100 EMU
- Keep-with-next enabled

**Body Text:**
- Regular: 11pt Public Sans, `ink` (#1B1B1B)
- Space Before Paragraph: 38100 EMU
- Space After Paragraph: 63500 EMU

**Lists — always Word's own bullets and numbering, never typed markers:**
- **Bullets** use Word's built-in **List Bullet** style (List Bullet 2 for a
  sub-list), including inside tables. Never a typed "•" or "-".
- **Numbered lists, numbered section headings, and discussion-guide questions**
  use Word's own numbering (the generator adds a definition to
  `numbering.xml` and attaches each paragraph with `numPr`), so the numbers
  are live and renumber when an item or section is added or removed. Never
  typed "1." text, and never a decimal outline (1.1, 1.2, 2.1).
- Items that carry an identifier rather than a position (RQ3, H1a) keep it as a
  bold label; that's a name, not list numbering.
- 11pt Public Sans, Regular; 0.25" indent per level; 31750 EMU after each
  item.

### Professional Spacing

- Section breaks: Generous white space (76200 EMU)
- Between paragraphs: Consistent 38100–63500 EMU
- After lists: 50800 EMU before next section
- Table spacing: 50800 EMU before and after

## Structural Elements

### Callout Boxes

Used for key information, decisions, and questions:
- Single-cell table with `base-lightest` background (#F0F0F0)
- Thick left accent bar in `primary` (#005EA2)
- Title in bold, `primary` (#005EA2), 12pt
- Content in italic `ink` (#1B1B1B), 11pt
- Padding: 50800 EMU top and bottom
- Followed by 50800 EMU spacing

**When to use:**
- Central research question
- Key decision points
- Important constraints or assumptions
- Success criteria

### Tables

**Header Row:**
- Background: `base-lightest` (#F0F0F0)
- Text: Bold, `ink` (#1B1B1B), 10.5pt Public Sans
- Repeats automatically across page breaks

**Data Rows:**
- Text: Regular `ink`, 10.5pt Public Sans
- Consistent column widths (narrow first column for timeline tables)
- Clear cell borders

**Style:** "Light Grid Accent 1" (or equivalent)

## Research Plan Format

Every research plan generated follows this structure:

1. **Title & Metadata** (Strategic Framing)
   - Product name (Main Title, `primary`)
   - Plan type (Subtitle, `base-dark`)
   - Context (metadata section)

2. **Purpose & Central Question**
   - Why this research matters
   - Central research question in callout box

3. **Scope Boundaries**
   - Two-column In Scope / Out of Scope table
   - Items are bulleted, regular weight (never bold), and concise — one short line each (~5–7 items per column)
   - Clear constraints and rationale in the intro paragraph

4. **Core Research Questions**
   - Grouped by theme or priority
   - Mapped to decisions they inform

5. **Participants & Recruitment**
   - Target profile
   - Disqualifiers
   - Recruitment strategy with priority ordering

6. **Discussion Guide** (if included)
   - Sections with time allocations
   - Questions numbered sequentially across the whole guide (1, 2, 3 …) by
     Word's own numbering, never a decimal outline (1.1, 2.1). A multi-part
     question shows its first part as "5." and the rest as "5b.", "5c.",
     indented under it: Word needs the numbered line before a lettered one.
     Numbers renumber while you draft, so give the moderator a final printed
     or PDF copy
   - Probes and moderator notes
   - Research question mappings

7. **Timeline & Milestones**
   - Week-by-week breakdown
   - Clear output/deliverable per phase

8. **Deliverables**
   - What the research will produce
   - Success criteria
   - Confidence notes

## Findings Report Format

Every written findings report follows this structure (full recipe, tier
rules, and worked examples in
`skills/research-findings-report/references/report-structure.md`):

1. **Title & Metadata** — product, "UX Research Findings & Recommendations,"
   contributors with roles, date, and the declared destination (title page
   *and* footer note)
2. **Executive Summary** (≤ half a page) — headline finding first, as a
   callout box; the decision it informs; featured findings as one-liners with
   exact counts and confidence
3. **Method Note** (≤ a third of a page) — n, persona, method, dates, and the
   limits that most constrain the findings; full detail in the appendix
4. **Findings** — 3–6 featured, ordered by importance, visual weight tracking
   evidence strength; each with a claim-as-heading, exact counts, one
   verbatim quote, interpretation marked as the researcher's read, and
   confidence + limits in the body
5. **Recommendations** — design-system table: # / Action / Owner / Depends on
   / Horizon / Confidence
6. **What This Means for You** (optional) — a line or two per audience
7. **Reviewer Notes** — flags from the gates, or an explicit "no open flags"
8. **Appendix** — summarized in the `.docx`, full content in a companion
   `.md` file (full findings records, coverage matrix, method detail,
   participant profile, recommendation alternatives)
9. **Additional Materials** — linked list: name, one-line description,
   location, access note

**Body budget: 3–5 rendered pages** before appendix and materials. The
`.docx` renders through the Research Document Template's `sections` layout,
so it inherits the palette, Public Sans, callouts, and tables above. Naming:
`[Product]_[ResearchType]_FindingsReport_[Date].docx` plus
`..._Appendix.md` alongside.

## Participant Summary Format (participant-facing)

The close-the-loop artifact that goes back to the people who were
interviewed. Governed by `skills/research-participant-summary-card/SKILL.md`;
full build reference in that skill's
`references/at-a-glance-card.md`.

**Default format — the "At a Glance" card.** One page, portrait, 1200 × 1500
CSS px, exported as PNG at 2× (2400 × 3000). Six zones:

1. **Eyebrow** — `[Team name]  |  [Product]`, uppercase, `base-dark`
2. **Title** — `What You Told Us About Adopting [Product]`, `primary`, 50pt,
   two lines; subtitle in `base-dark`, then a 4px `primary` rule
3. **Three stat tiles** — `base-lightest` fill, 6px `primary` left bar, 40pt figure.
   Never a session duration
4. **Headline callout** — `base-lightest` with `primary` accent bar, one sentence
5. **Three numbered conditions** — 1px `#DFE1E2` (`base-lighter`) border, 52px `primary`
   numbered square, bold title, supporting line opening with "You told us…"
6. **Secondary list** — 10px `primary` square bullets, three items

Footer: 1px top border, thank-you at left, anonymization disclosure plus
**month and year** at right.

**This format has a stricter data bar than any internal document:** no
participant IDs, no exact prevalence counts, no verbatim quotes, no company
or account names. That inverts the usual rule in "Data Integrity Standards"
below — because the audience changed, not because the standard relaxed. At a
four-person account, "3 of 4" is identifying.

Naming: `[Product]_ParticipantSummary_AtAGlance_[YYYY-MM].png`, with its
`.html` source kept alongside so copy can be re-rendered.

Alternative formats produced by this skill: a "You said / We heard" `.docx`
one-pager (via the Research Document Template) and a slide summary. The email
that carries them is drafted by `skills/participant-impact-summary/`.

## Deck (Presentation) Format

Every readout deck follows this structure:

- **Slide Master:** the USWDS palette above, in Public Sans
- **Title Slides:** Bold heading, Professional blue
- **Content Slides:** Evidence → Interpretation → Insight → Recommendation
- **Visual Hierarchy:** Large headings (44pt), body text (24pt)
- **Callouts:** Key findings in color-highlighted boxes
- **Evidence Display:** Verbatim quotes with participant IDs
- **Recommendations:** Clear ownership and next steps

See `research-readout-deck/references/deck-structure.md` for full slide-by-slide guidance.

## Data Integrity Standards

Every output must include or reference:

### For Research Plans
- **Participant screener logic** — Exactly who you're talking to
- **Recruitment contingencies** — What if you don't hit your targets?
- **Analysis methodology** — How you'll reach findings
- **Scope boundaries** — Explicitly what's NOT being researched

### For Findings & Synthesis
- **Evidence traceability** — Every claim is linked to:
  - Verbatim quote + Participant ID (e.g., "P02 said: '...'")
  - Or: Observation in raw notes (e.g., "Session 3 notes, min 12:34")
- **Distinction between observation, interpretation, insight, recommendation**
  - Observation = What you heard/saw (not interpreted)
  - Interpretation = What it means in context
  - Insight = The pattern or tension (not a recommendation)
  - Recommendation = What to do about it (owned by a role)

### For Competitive Analysis
- **Claim labels:** [verified], [vendor claim], [inference], [unknown]
- **Source dating:** All volatile information dated
- **Visual evidence sourcing:** Every screenshot labeled by type ([live product], [marketing], [demo video], [third party])

## Quality Checklist

Before sharing any document, verify:

**Visual Design:**
- ✅ Document font is Public Sans throughout (including tables and footers)
- ✅ Title and H1 headings are `primary` (#005EA2)
- ✅ Section headings (H2) are `base-dark` (#565C65)
- ✅ Callout boxes have `base-lightest` (#F0F0F0) background with a #005EA2 accent bar
- ✅ Bullets and numbers are Word's own (List Bullet, live numbering), never typed
- ✅ Section numbering has no gaps (Word numbering handles omitted sections)
- ✅ Spacing is consistent (no cramped text)
- ✅ Tables have colored headers
- ✅ Page numbers appear in the footer

**Structural Integrity:**
- ✅ Research plan has scope boundaries (in/out of scope)
- ✅ All claims reference evidence (quotes + participant IDs)
- ✅ Findings distinguish observation → interpretation → insight
- ✅ Recommendations have named owners
- ✅ Deliverables are clear and achievable

**Professional Quality:**
- ✅ No orphaned headings
- ✅ No half-empty tables
- ✅ Consistent formatting throughout
- ✅ Proofread and spell-checked
- ✅ Ready for stakeholder presentation

**Writing** — full standard and 23-item rubric in [`VOICE-AND-STYLE.md`](VOICE-AND-STYLE.md):
- ✅ Leads with the answer, not the method
- ✅ Sentence length varies (uniform rhythm is the strongest generated-text tell)
- ✅ Quantifiers are exact — "6 of 8," never "most" or "several"
- ✅ At least one verbatim quote per major finding
- ✅ At least one concrete detail that could only come from being in the room
- ✅ Confidence and limits stated in the researcher's own voice
- ✅ The summary concludes rather than restates
- ✅ Acronyms expanded on first use; research-process jargon confined to the method note
- ✅ No sentence interrupted by an em dash or en dash — finish the thought, then a new sentence or a bracketed aside (`VOICE-AND-STYLE.md` item 22)
- ✅ No participant-identifying data — including speaker notes, alt text, and screenshots

This design system governs how a document **looks**. `VOICE-AND-STYLE.md` governs how
it **reads**. Both are checked before release; styling alone has never made a document
credible.

## Maintaining Consistency

### For Skills Developers

When creating a new skill that produces documents:

1. **Reference this design system** in your skill's frontmatter:
   ```
   design-system: DESIGN-SYSTEM.md
   output-standard: research-plan / readout-deck / analysis-matrix
   ```

2. **Use the Research Document Template** for any plan output:
   ```python
   from research_document_template import ResearchDocumentTemplate
   ```

3. **Test styling** against the checklist above before finalizing

4. **Document any deviations** — if your output differs (e.g., analysis matrices), explain why

### For Dr. Morgan Agent

Dr. Morgan should refer users to the Research Document Template **whenever a research document is being produced** — plans, rationales, briefs alike:

> "To create a professional research document with built-in styling and structure, I recommend using the **Research Document Template skill**. Invoke it with `/research-document-template` and provide your research context. It will generate a Word document following the suite's design standards (USWDS palette, Public Sans)."

### For Quality Assurance

Before releasing any research, run the gates in [`EVALUATION-LOOP.md`](EVALUATION-LOOP.md).
Safety pre-flight first on every artifact, then the quality gates in order. The
matrix of which gates apply to which artifact lives in §3 of that file and is
deliberately not repeated here.

Then:

1. Check against the **Quality Checklist** above
2. Have a peer review the styling and structure
3. Attach any gate flags to the document as **Reviewer Notes** so the human sees them
   at the moment of decision, not in a report they've already closed

The gates cap out at two revision passes. If an artifact still fails after that, the
problem is upstream of the formatting — escalate rather than reformatting again.
